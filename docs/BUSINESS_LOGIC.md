# Бизнес-логика и Сценарии (Edge Cases)

## 1. Механизм Gatekeeper (Web Portal)
- Работает при входе через SSO. Проверяет флаг `is_verified`.
- **Grace Period**: Если данные не верифицированы, но `grace_period_left > 0`, пользователю доступна кнопка "Пропустить". При нажатии `grace_period_left` уменьшается на 1.
- При `grace_period_left == 0` — жесткий блок (Hard Block) до актуализации данных.

## 2. Логика валидации (Контроль качества)
- **Учет OOO (Out of office)**: Если по данным AD/Exchange сотрудник в отпуске или на больничном, система замораживает требования по верификации.
- **Обработка Telegram-репортов**: 
    - Репорт на профиль `is_protected = True` создает тикет тихо для IT, не меняя статус профиля.
    - Множественные репорты от разных пользователей меняют статус `change_requests` на `conflict`.

## 3. Ролевая модель (Панели управления)
- **IT-Operator**: Имеет доступ к "Пульту управления инцидентами". Разрешает записи со статусом `conflict`. Может включить форсированную синхронизацию ("Force Sync").
- **Department Head**: Имеет доступ к дашборду своего подразделения (фильтр по `department`). Одобряет структурные изменения и видит метрики заполненности профилей своих подчиненных.
