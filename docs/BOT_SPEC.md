# Интеграция Telegram-бота (Спецификация для внешнего разработчика AI-ассистента)

> [!IMPORTANT]
> **Архитектурное решение:** Telegram-бот является **полностью внешним, независимым проектом**. 
> В данном репозитории (`smart-contacts`) код бота **НЕ СОДЕРЖИТСЯ** и **НЕ РАЗРАБАТЫВАЕТСЯ**. 
> Этот документ существует исключительно как спецификация API-контракта для передачи разработчику бота.

---

## 1. Архитектура бота (AI Ассистент)

Телеграм-бот реализован как **AI-ассистент** (на базе Gemini API или аналогичной LLM). 
Бот общается с пользователями на естественном языке, а для взаимодействия с базой данных контактов он использует **function calling (вызов инструментов)**.

Прямой доступ к базе данных `PostgreSQL` для бота закрыт. Все вызовы инструментов транслируются в HTTP-запросы к нашему `API Gateway`.

### 1.1 Авторизация
Бот использует долговечный сервисный JWT-токен. 
Все запросы к API должны содержать заголовок:
`Authorization: Bearer <СЕРВИСНЫЙ_ТОКЕН_БОТА>`

---

## 2. Взаимодействие с API Gateway

API предоставляет два основных эндпоинта. Один используется как инструмент для AI, другой — как обработчик стандартной команды.

### 2.1 Инструмент для LLM: `search_contacts`

Используется AI-ассистентом (Gemini), когда пользователь просит найти телефон, добавочный номер, кабинет или отдел сотрудника. Общение идет на естественном языке, жестких команд для поиска нет.

* **REST API Метод:** `GET /api/v1/users`
* **Query параметры:**
  * `q` (string) - Поисковая фраза (ФИО, название отдела).
  * `limit` (int) - Максимальное количество результатов (рекомендуется 5).

**Пример ответа от API (для передачи в контекст LLM):**
```json
{
  "total": 1,
  "page": 1,
  "limit": 5,
  "items": [
    {
      "id": "123e4567-e89b-12d3-a456-426614174000",
      "full_name": "Иванов Иван Иванович",
      "internal_phone": "49-87",
      "mobile_phone": "+79161234567",
      "department": "ИТ-отдел",
      "office_location": "Офис А, каб. 301"
    }
  ]
}
```
*Примечание: Если пользователь VIP (`is_protected = true`), API вернет `internal_phone: null`. LLM должна корректно сообщить пользователю, что внутренний номер скрыт настройками приватности.*

### 2.2 Обработка команды: `/report`

Эта функция реализована в боте как **классическая команда** (вне контекста LLM). Используется для создания жалобы на неактуальные контактные данные.

* **REST API Метод:** `POST /api/v1/reports`
* **Тело запроса (JSON):**
```json
{
  "target_user_id": "123e4567-e89b-12d3-a456-426614174000",
  "reason": "Введенная пользователем причина"
}
```

**Пример ответа (201 Created):**
```json
{
  "id": "uuid",
  "status": "new"
}
```

## 3. Зона ответственности бота (MVP)

На данный момент реализация бота фокусируется на гибридном подходе: AI-помощник для поиска + стандартная команда для жалоб.

Задачи разработчика внешнего бота:
1. Настроить системный промпт для Gemini API, описывающий роль корпоративного справочника.
2. Подключить инструмент (tool) `search_contacts` для LLM, чтобы она могла искать контакты по запросу пользователя.
3. Реализовать классический обработчик команды `/report` для сбора жалоб от пользователей и отправки их в API.
4. Хранить `BOT_TOKEN`, `GEMINI_API_KEY` и `API_BASE_URL` в своей независимой инфраструктуре.
